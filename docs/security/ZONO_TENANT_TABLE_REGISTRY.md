# ZONO — Tenant Table Registry

Classification of every `public` table by isolation class, from the live inventory (~340 tables). Classes: **GLOBAL** (reference, no tenant) · **TENANT** (org-owned) · **USER** (user-owned within org) · **JOB** (system/cron) · **ANALYTICS** (aggregate) · **INTEGRATION** (external creds/sync) · **SENSITIVE** (documents/PII/financial) · **LEGACY** (unused shell).

## Policy
Every TENANT/USER/SENSITIVE record must resolve to exactly one `organization_id` (unless an explicitly-defined shared record). **DB-enforced RLS is the boundary; the application-layer `org-scope` write helper is the second layer, not the sole one.** Global reference tables may be world-readable but write-locked.

## Classification (representative; full CSV to be generated by the registry query)

| Class | Examples | Isolation requirement |
|---|---|---|
| GLOBAL | `israel_localities`, `neighborhoods`, `roles`, `automation_templates`, `legal_templates`, `broker_profiles`/`brokerage_offices` (external market data) | read-public OK; writes locked; **no org_id needed** |
| TENANT | `organizations`, `buyers`, `sellers`, `leads`, `deals`, `properties`, `tasks`, `notes`, `meetings`, `documents`, `journeys`, `opportunity_signals`, `match_intelligence_profiles`, `communication_*`, `whatsapp_*`, `automation_workflows/runs`, `territory_*`, `import_*`, `persons`/`person_*` (new) | **RLS on org_id required** |
| USER | records with `owner_id`/`assigned_agent_id` (buyers, leads, tasks, deals) | org RLS + ownership checks in write helper |
| JOB | `zono_orchestrator_runs`, `engine_runs`, `*_refresh_runs`, `research_jobs`, `domain_events`, `domain_event_deliveries` | org-scope where tenant-derived; service-role only |
| ANALYTICS | `bi_snapshots`, `team_performance_snapshots`, `brokerage_market_share`, `zono_compute_cache` | org-scope; derived, no direct client write |
| INTEGRATION | `google_connections`, `whatsapp_accounts`, `social_connection_vault`, `distribution_provider_connections` | **SENSITIVE creds — RLS + encryption at rest** |
| SENSITIVE | `documents`, `document_signatures`, `legal_documents`, `buyer_financial_profiles`, `persons` (PII/ת"ז), commission tables (future) | RLS + private storage + audit on access |
| LEGACY/empty | ~150 tables with 0 rows and no wiring (`community_*`, many `zono_*`, `agency_*`, `radar_*`) | audit: enable RLS or drop; do not expose |

## Action items
1. **Generate the exhaustive registry** via an information_schema + pg_policies query, emitting per table: `organization_id` column present? FK path to org? RLS enabled? policy count? service-role write sites? → `tenant_table_registry.csv`.
2. **Every TENANT/USER/SENSITIVE table lacking a policy is a P0 line item** — the audit found ~109. Enable org-scoped RLS (SELECT) + route writes through `org-scope`.
3. **Add a CI lint** failing the build when a table classified TENANT/USER/SENSITIVE has no RLS policy.
4. **Global tables** get an explicit allow-read/lock-write policy so "no policy" never silently means "open."

## Ownership-chain notes
- `organization_id` is the primary key on most tenant tables (good).
- A few use an indirect FK path (e.g. `property_intelligence_profiles.property_id → properties.organization_id`) — these need either a denormalized `organization_id` or a policy joining to the parent. Flag each in the registry.
- `users.email` is globally `UNIQUE` — a person cannot belong to two orgs; note for multi-org future.
