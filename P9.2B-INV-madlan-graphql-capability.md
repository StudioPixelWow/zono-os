## 1. MADLAN EXISTING GRAPHQL CAPABILITY — CONFIRMED REAL (sanctioned)

We already operate a sanctioned path to Madlan's **public GraphQL API** via `swerve/madlan-analytics` (used in `src/lib/transactions/madlan.ts` for `dataTypes:["deals"]`). Its own docs: *"queries Madlan's public GraphQL API directly. No proxy or anti-bot bypass required."* Real evidence from our code:

- **Locality resolver** `madlanDocId(city)` produces the slug **`{city}-ישראל`** (e.g. `רחובות-ישראל`) — the **same locality format** as the directory routes `/madad-search/{city}-ישראל`. This is concrete evidence the GraphQL locality addressing already matches the directory's addressing.
- **Input contract** we already use: `{ city, dataTypes: string[], neighbourhood? }`.

So: a sanctioned, anti-bot-free GraphQL channel to Madlan **exists and is proven in production** — and its locality resolver lines up with the directory URLs.

## 2. MADLAN-SCRAPER RAW IDENTITY FIELDS — measured from 770 stored rows

We store the **full raw actor output** of `swerve/madlan-scraper` in `external_listings.metadata.raw_data`. Enumerating every key across **770 Madlan rows** (each key present in all 770), the complete raw contract is:

`address, areaSqm, bathrooms, city, cityHebrew, condition, contactName, contactPhone, contactType, currency, dealType, description, firstSeen, floor, floorplanImages, hasAgent, hasAirConditioning, hasBalcony, hasBasement, hasElevator, hasGarden, hasPool, hasSecureRoom, hasTerrace, id, images, isBarrierFree, isFurnished, latitude, longitude, neighbourhood, parking, petsAllowed, price, pricePerSqm, propertyType, rooms, scrapedAt, streetName, streetNumber, totalFloors, url, vaadBait, yearBuilt, zipcode`

**Identity fields actually present:** `contactName` (display name), `contactPhone`, `contactType` (`agent`|`private`), `hasAgent`, and the **listing** `id` + `url`.
Agent breakdown in our data: **546** agent-type rows (134 distinct contact names, 495 distinct phones) vs **224** private.

**Directory identity fields ABSENT (verified, not present in any of the 770 rows):** agent entity id · office/agency id · agency/office **name** · agent profile URL · office profile URL · Madlan entity id (`re_office_…`) · seller/account id.

⇒ **We are NOT discarding directory identity during normalization — it is not in the listings actor output at all.** The only broker signal it carries is display-name + phone + agent/private flag, i.e. exactly the weak name/phone inference the approved model forbids as a sole basis.
