## 2. Provider contract

`discoverCityDirectory(locality)` → normalized `CityDirectoryFetch`:

```
{ source, locality, status, offices[], agents[], relationships[], pagination, observedAt, reason }
```

- **Office**: `sourceEntityId` (e.g. `re_office_…`), `displayName`, `normalizedName`, `profileUrl`, `city`, `phone`, `address`, `website`, `brandNetwork`, `sourceMetadata`.
- **Agent**: `sourceEntityId`, `displayName`, `normalizedName`, `profileUrl`, `city`, `phone`, `role`, `officeSourceEntityId`, `sourceMetadata`.
- **Relationship**: `agentSourceEntityId` → `officeSourceEntityId`, `source`, `observedAt`.
- **status** ∈ `success | partial | provider_not_configured | provider_blocked | error`. Only fields the source truly exposes are populated — nothing invented. The normalizer (`provider.ts`) is the single defensive adaptation point (multi-key `pick()`, same strategy as the listings input adapter).

## 3. Refresh cadence

**Directory = DAILY** (`/api/cron/madlan-directory-refresh`, cron `30 3 * * *`); **listing activity = HOURLY** (the untouched `external-listings-sync` gate). Rationale: office membership changes far more slowly than listing inventory, so re-fetching a slow-moving directory hourly would waste provider load/cost with no freshness benefit. The daily cron refreshes each **operating** city (distinct cities in active `external_listings`), stalest-first, time-boxed (250s soft budget), one run row per city. **Directory = WHO EXISTS · Hourly Watch = WHAT CHANGED** — complementary, never merged.

## 13. Freshness

Every upsert stamps `first_seen_at` (insert only), `last_seen_at`, `last_verified_at`. Re-runs refresh `last_seen_at`/`last_verified_at` without creating rows.

## 14. Directory vs activity proof

`computeDirectoryActivity(locality)` returns **separate** metrics: `directoryOffices / directoryAgents / directoryRelationships / agentsUnresolved` (presence) vs `observedActiveOffices / observedActiveAgents / observedListings` (derived by joining directory identities' phones to **active** `external_listings`). "Active" is computed, never a `status` mutation. An office can exist with 0 observed listings — represented honestly.

## 15. Duplicate protection (idempotency by construction)

Office key = `madlan_entity_id` → else `normalized_name + sameCity`. Agent key = `madlan_entity_id` → else `normalized_name + sameCity`. In-run `seenKeys` de-dupe (increment `duplicatesMerged`), and find-before-insert across runs. Identity is idempotent by `agent_id`. Same office → same canonical office; same broker → same canonical broker; same relationship → refreshed freshness. No duplicate entities per run.

## 16. Secondary inference integration

`ai-candidate-seeding`, `office-resolution`, `broker-research`, phone/name attribution are **kept and demoted** — none deleted. Directory writes set `resolution_method='madlan_directory'` (strong provenance), so a weak phone/name guess can enrich or add supporting evidence but **cannot override** a source-stated relationship. Inference still discovers offices absent from Madlan and connects current listings to directory identities.
