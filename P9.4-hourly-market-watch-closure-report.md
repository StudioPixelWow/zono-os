## 3. Global invocation deadline

`HARD_LIMIT = 300s`, `SAFETY_MARGIN = 60s`, **`APPLICATION_DEADLINE = 240s`**, passed as an absolute epoch-ms `deadline` into every org sync. The app stops itself; it does not wait for Vercel's kill.

## 4. Per-org budget behavior

Before starting an org the route calls the pure `orgBudgetDecision({remaining, est, minStart, safety, deadline})`: **run** (enough budget), **defer** (won't fit — try smaller orgs behind it), or **stop** (out of budget — defer the rest). `est` = the org's last terminal run `duration_ms` (fallback 120s, ×1.25 safety); `minStart = 45s`. A deferred org gets a **terminal `deferred` run row** (`reason: insufficient_budget`), never a zombie.

## 5. Large org interruptibility (the critical fix)

Deadline awareness now lives INSIDE the org sync (`service.ts`): the city loop checks `pastDeadline()` before each city (deferring remaining cities via the existing cursor), and — the key change — the **heavy enrichment chain is gated by `enrichmentBudgetOk(deadline, reserve=40s)`**. If the deadline (minus reserve) is reached, the listings are already persisted and the analytics is **deferred** (`summary.enrichmentDeferred`), split so the essentials (lifecycle/signals/scores/aggregates) run first and the heavy tail (MAI‑6…13) re-checks budget. A large org now exits cleanly ~PARTIAL instead of overrunning.

## 6. City chunking

Multi-locality orgs already checkpoint a `cursorRemaining` per city; the deadline break in the city loop + that cursor = incremental cities across invocations. Completed cities are not re-done.

## 7. Provider budget / failure isolation

Sources run **sequentially with a per-source try/catch** (unchanged, already correct): Yad2 failing preserves Madlan and vice-versa → **PARTIAL, not total failure**; existing external data is never deleted on a provider failure. Providers are each bounded (~100s actor cap). Harness **E** covers this.

## 8. Fairness / no starvation

Stalest-first by last `import_jobs` timestamp. A deferred org writes **no** import_job (it didn't sync), so it stays stalest → **first next run**. The route `continue`s past a too-big org to fill remaining budget with smaller ones, so no org is skipped while budget exists, and no org starves. Algorithm returned in §4/§8; no hardcoded org.

## 9. Fairness algorithm

`orderByStalestScan` (oldest import_job first) → per-org `orgBudgetDecision` → run/defer/stop. Deferred → stalest → front next hour. Bounded fairness, deterministic.
